- [x] **1. Build payments CRUD with status transition logic.** Register a payment (`amount`, `method` enum, `date`, `note`) against a contract, scoped per §5 (`normal` only on contracts they created). After each payment, recompute `paymentStatus` from the contract's cumulative paid amount vs. `deposit` and `total`:
  - cumulative paid `<` `deposit` → stays `pending`
  - cumulative paid crosses `deposit` for the first time (was below, now at or above, and still `< total`) → `deposit_paid`, and this is also the trigger that flips `contractStatus` from `pre_contract` to `confirmed` (spec §6.4)
  - a further payment recorded after `deposit_paid` has already been reached, while still `< total` → `partial`
  - cumulative paid `>= total` → `paid_in_full`

  This rule is confirmed (spec §12, item 6) — implement it as specified, no further confirmation needed.

  **Bug #1 (found and fixed) — sidebar nav was broken on first mobile visit, on every page.** `src/components/sidebar-nav.tsx` renders the full text label (`<span>{item.label}</span>`, lines ~44 and ~94) purely off the `collapsed` boolean prop, with no viewport check. `src/components/app-shell.tsx`'s `<aside>` is CSS-forced to `w-16` (64px) below the `md` (768px) breakpoint *regardless* of `collapsed` (`collapsed ? "w-16" : "w-16 md:w-[236px]"`). `defaultCollapsed` comes from the `sidebar_collapsed` cookie (`src/app/(app)/layout.tsx:12`), which is absent for any new session. Net effect: a first-time visitor on a phone — i.e. the normal case, not an edge case — got full nav labels truncated/clipped inside a 64px rail on literally every page. Confirmed root cause by forcing `sidebar_collapsed=1` via cookie: rendered correctly (clean icon rail) once collapsed. **Fixed** by making the label rendering itself viewport-aware (`hidden md:inline` on the label span, not just the JS boolean) in both `sidebar-nav.tsx` and the same defect's instance in `user-chip.tsx`; re-verified via Playwright at 375px/768px/1440px with no regression on desktop/tablet.

  **Bug #2 (found and fixed) — contract detail page scrolled horizontally at 375px.** On `/contratos/[id]`, `document.documentElement.scrollWidth` was 670px against a 375px viewport (confirmed via DOM measurement + screenshot). Traced to `src/app/(app)/contratos/[id]/copy-viewer-link.tsx`'s "Enlace para el cliente" row: the URL `<span className="min-w-0 flex-1 truncate ...">` did not actually shrink to the `flex flex-wrap items-center gap-2` row's available width despite `min-w-0`/`truncate`, so the row (and the whole page body) was forced wide enough to fit the un-wrapped ~74-character viewer URL. Not reproducible at 768px (tablet) — phone-width-specific. This is on the payment UI page, one of the four pages task 8 explicitly names. **Fixed** by adding a base `grid-cols-1` to the grid container in `page.tsx` before its `lg:` override; re-verified — `scrollWidth` now matches the viewport width exactly at 375px, with no regression at 768px/1440px.
